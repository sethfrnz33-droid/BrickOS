# Brick Tuner Suite v4.1 — 3D map, HOME Menu 3D model, compact UI

## Implemented source changes

- Restored in-app interface graphics to v3.9 (no chenille PNG or 3D logo embedded on the six-gauge dashboard).
- Improved the existing real-ECU height-field renderer: height now uses the spread of verified original table readings, not the INI's much larger allowed editing bounds; distinct five-colour cell heatmap; 3D sidewalls, perspective and a highlighted selected cell.
- Depth-aware left/right parallax now reacts visibly to the Nintendo 3DS 3D slider, while Circle Pad and D-pad still rotate the view without writing to the ECU.
- Constant/invalid ECU readings display an explicit explanation instead of synthesizing a fake nonzero map.
- Removed redundant additional-gauge heading, slightly enlarged fallback instrument numbers.
- Removed duplicate TunerStudio category title on the lower screen, showing seven selectable real INI items at the original readable font size instead of six. Touch coordinates adjusted accordingly. Shortened the top TUNE heading.
- Converted banner audio to 44.1 kHz, 16-bit stereo PCM for HOME Menu compatibility (0.64 sec original sample retained).
- Added a compact version of the user's actual 3D chenille wordmark as a glTF/GLB banner asset (1,106 triangles instead of 34,120). Included original model untouched.
- Wired CIA packaging for a CGFX Extended Banner, not a static PNG. Generates CGFX using pycgfx at build time when Python, Git and network are available.

## Verification

- 19 host regression scripts passed (including native C execution with nonzero U16 calibration bytes, five heat bands, >55px surface height spread, stereo parallax, and a constant-value warning).
- Full host C syntax checked. No devkitARM compiler, 3DS GPU, actual ECU, or CGFX compiler available here; native console behavior is **unverified**.
- `home-banner/banner.cgfx` and `banner.bnr` are generated by the supplied build script and are **not** precompiled or shipped.
