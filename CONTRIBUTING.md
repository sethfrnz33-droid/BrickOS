# Contributing to BrickOS planning

A proposed calibration expert must identify: (1) firmware compatibility, (2) exact INI field identities, (3) required live channels, (4) active-strategy predicate, (5) evidence-admission rules, (6) candidate explanations and missing evidence, (7) read-only outputs, (8) dependency invalidation, (9) hardware validation gate, (10) explicit behavior when data is unknown. Claims of automatic optimization need independent evidence and must not assume absence of faults proves safety.

Maintain the documentation's explicit `DESIGNED / HOST_TESTED / ESP_BUILT / BENCH_VALIDATED / PROFESSIONALLY_VALIDATED` labels. Never add real customer calibrations, authentication secrets or identifying log data to a public repository. Keep manual tuning unchanged unless a separately approved user request targets it.
